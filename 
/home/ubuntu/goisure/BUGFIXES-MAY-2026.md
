
# Bug Fixes - May 2026
## Critical Production Fixes

### Overview
Fixed 5 critical bugs in the AI processing pipeline that were causing cases to stall and the dashboard to show "case not found" after processing.

### Root Causes

All bugs were in `/home/ubuntu/goisure/backend/server.py` in the `process_ai()` function:

1. **Duplicate API key lookup** (line ~1710)
   - Same line `api_key = os.environ.get("OPENROUTER_API_KEY", "")` appeared twice
   - Redundant but harmless

2. **Critical: if-not-elif control flow bug** (lines 1712-1724)
   - Original: `if not api_key: ... elif api_key:`
   - **Impact**: When key was loaded from file, the `if` block ran, then `elif` was skipped → AI never ran
   - **Fix**: Changed to independent `if api_key:` after file-load attempt

3. **Critical: Missing claims_amounts initialization** (line ~1792)
   - Code tried `claims_amounts.append()` without `claims_amounts = []` first
   - **Impact**: `NameError` crash in fallback merge path
   - **Fix**: Added `claims_amounts = []` before loop

4. **Critical: Missing analytics variable** (after key_stats ~line 1995)
   - Code referenced `analytics` in DB update but never defined it
   - **Impact**: `NameError` crash
   - **Fix**: Added full analytics calculation from `structured_data`

5. **Undefined variable 'ca'** (lines ~2092, ~2114)
   - Code used `ca.get("claims_analysis")` but `ca` was never defined
   - **Impact**: `NameError` crash
   - **Fix**: Changed to `analytics.get("claims_analysis")`

### Additional Frontend Fix

**AIInsightsPage.js** - API URL hardcoded to localhost:
- Original: `const API = process.env.REACT_APP_API_URL || 'http://localhost:8000';`
- Issue: Browser called `localhost:8000` from user's machine (not the server)
- Fix: `const API = process.env.REACT_APP_API_URL || '';` (relative `/api` path)
- Also fixed `runProcessAI` endpoint URL
